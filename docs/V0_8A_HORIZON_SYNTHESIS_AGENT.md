# V0.8A Step 4 — Horizon Synthesis Agent

## Role and execution boundary

`src/horizon_synthesis.py` implements `synthesize_horizon(context)` under
`horizon-synthesis-v1`. It immediately invokes `require_synthesis_ready` and uses
the recomputed context. Rejected, blocked or forged contexts cause zero OpenAI calls;
readiness errors retain their reasons. No research is refreshed or regenerated.

Deterministic Python owns admission, freshness, applicability, authority, conflict,
policy versions and matrix constraints. The agent interprets only admitted evidence.
The same existing OpenAI client/model uses Responses, strict JSON schema,
`require_completed=True`, output_text extraction, JSON decoding and local validation.
There is one request, no retry, fallback, specialist rerun or persistence.

## Result and provenance

The frozen IntegratedResearchView composes the complete validated context with an
immutable JSON interpretation, application UTC completion timestamp, model identity
and synthesis methodology. Its accessor returns a detached dictionary. Source
conclusions, native horizons, confidence, conditions, evidence, provenance and limits
remain unchanged in the context. They are not regenerated by the model.

The model echoes ticker, decision horizon, authority, conflict and both conclusions;
all must match exactly. Other trusted metadata is retained by composition rather
than entrusted to AI. The prompt includes the source catalog rows and interpretations,
not raw historical bars or Fundamental portfolio_assessment. Source namespaces stay
separate. No portfolio position, weight, cost, cash or concentration is consumed.

## Research-only posture and confidence

Approved postures are FAVORABLE_NOW, WAIT_FOR_CONFIRMATION, UNFAVORABLE_NOW,
NO_ACTION and UNRESOLVED. Matrix rows define permitted ranges, never select output.
As explicitly allowed in Step 4, UNRESOLVED is available for residual interpretive
ambiguity in a ready context; it cannot bypass blocked input. NO_ACTION is an informed
lack of a compelling stance, not a failure fallback. WAIT must cite a supplied
condition in its summary.

Confidence is an independently assigned integer 0–100 measuring evidence strength
for the combined interpretation. It is not profit probability, expected return,
accuracy or an arithmetic transformation of specialist scores. No weights or
confidence arithmetic are implemented.

## Evidence, conditions and limits

Each statement has separate Fundamental/Technical evidence IDs, classification and
condition references. Every citation must exist; unavailable Technical evidence
cannot support a claim. Summary grounding requires both namespaces. Supporting and
conflicting lists remain separate. Source invalidation/confirmation lists are
preserved unchanged. Deterministic packet-local condition IDs reference those lists;
the model cannot introduce a new condition ID. Invalidation summaries must reference
original invalidations and their cited evidence.

AI_INTERPRETATION and FORECAST are the only generated statement categories.
Condition-bearing statements are FORECAST. Common explicit predictive language is
rejected outside FORECAST. Numeric facts stay in the catalogs: generated prose may
use exact cited indicator labels but no other digits. Explicit portfolio actions,
orders, stop levels and price-target language are rejected. This deliberately
conservative rule follows the existing Technical Analyst style.

All deterministic warning/missing-data tokens must be acknowledged exactly and in
order; the complete original limitations remain in the returned context regardless.
The output cannot erase them or change blockers into warnings.

## Failure handling

HorizonSynthesisError uses safe classifications: API_REQUEST, RESPONSE_EXTRACTION,
INVALID_JSON, SCHEMA_VALIDATION, INVALID_ENUM, INVALID_EVIDENCE_REFERENCE,
IDENTITY_MISMATCH or SEMANTIC_VALIDATION. Logs contain fixed stage/operation/type only,
never raw response text, prompts or keys. Readiness failures remain
SynthesisReadinessError. Malformed JSON and code fences are rejected, not repaired.

## Validation and limitations

Offline tests cover the real mocked Responses object path, single-call execution,
blocked/forged gates, all four horizons, enum/range/schema failures, exact identity,
namespace separation, conditions, numeric constraints, limitations and no reruns.
Parser-level tests cover every conflict echo; they do not manufacture publicly
accepted ready THESIS_CONFLICT contexts that Step 3B cannot currently produce.

Semantic validation does not prove natural-language entailment, detect every
qualitative invented fact, or certify all forecast wording. A valid citation does
not prove the prose follows from it. These limitations are explicit; schema success
is not investment quality. Step 3B's restrictive risk/applicability blockers remain.

Manual live synthesis validation is SKIPPED: available ready test contexts use mocked
Fundamental analysis and deliberately controlled Technical fixture conditions. They
exercise code contracts but do not establish a new independently validated research
artifact for a live smoke. No provider calls or specialist reruns are made to obtain
one. All unit calls are mocked.

No database/dashboard work or V0.8B portfolio actions are included. V0.8A remains in
progress; a future consumer must use the guarded entry point, not private parser helpers.
